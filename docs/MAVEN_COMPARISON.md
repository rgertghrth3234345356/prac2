# Сравнение с Maven dependency:tree

## Цель проверки

Сравнить транзитивное поддерево артефакта `org.slf4j:slf4j-simple:2.0.13`,
полученное приложением из POM-файлов, с тем же поддеревом в штатном выводе
Maven `dependency:tree`. Maven используется только для независимой проверки;
приложение не запускает Maven и не использует его для получения зависимостей.

## Проект-потребитель

В каталоге `docs/maven-comparison/` находится `pom.xml` небольшого проекта,
который зависит от `slf4j-simple:2.0.13`. Из корня репозитория выполните:

```bash
cd docs/maven-comparison
mvn dependency:tree
```

Ожидаемое поддерево выбранной зависимости (без корневого проекта-потребителя):

```text
org.slf4j:slf4j-simple:jar:2.0.13:compile
\- org.slf4j:slf4j-api:jar:2.0.13:compile
```

Maven может дополнительно вывести служебные сообщения загрузки плагина.
Для сравнения учитывайте только дерево зависимостей.

## Запуск Dependency Visualizer

Вернитесь в корень проекта и выполните:

```bash
cd ../..
python -m src.main --package org.slf4j:slf4j-simple:2.0.13 --repository https://repo.maven.apache.org/maven2 --ascii --order
```

Ожидаемая структура поддерева для этого примера:

```text
org.slf4j:slf4j-simple:2.0.13
`-- org.slf4j:slf4j-api:2.0.13
```

Для этого простого артефакта результаты должны совпасть по составу
зависимостей. В Maven-выводе есть дополнительный корневой проект-потребитель;
его не следует принимать за зависимость `slf4j-simple`.

## Сравнение порядка загрузки

Выполните в каталоге `docs/maven-comparison/`:

```bash
mvn dependency:build-classpath -Dmdep.outputFile=target/classpath.txt
```

Файл `target/classpath.txt` содержит порядок JAR-файлов для classpath. Для
этого примера Maven обычно ставит `slf4j-simple` перед его `slf4j-api`, потому
что classpath перечисляет прямую зависимость перед её транзитивной
зависимостью. Программа, напротив, выводит топологический порядок загрузки:
сначала `slf4j-api`, затем `slf4j-simple`. Это не ошибка графа: classpath
порядок и порядок установки — разные операции. Maven не задаёт отдельный
универсальный порядок физической установки артефактов, поэтому для сравнения
показываются и дерево зависимостей, и фактический classpath.

## Сопоставление

| Проверяемое свойство | Maven | Dependency Visualizer |
|---|---|---|
| Прямые зависимости | `dependency:tree` | Показывает |
| Транзитивные зависимости | `dependency:tree` | Обходит итеративным DFS |
| Порядок дерева | `dependency:tree` | Порядок обхода DFS |
| Порядок classpath | `dependency:build-classpath` | Не формирует classpath |
| Порядок загрузки | Определяется механизмом разрешения Maven | DFS postorder: зависимости раньше зависимых пакетов |
| Циклы | Обрабатываются механизмом разрешения Maven | Циклические рёбра сохраняются; линейный порядок отклоняется |

## Причины возможных расхождений

1. Maven строит эффективную модель проекта с учётом родительских POM и
   наследования свойств. Учебный парсер читает свойства текущего POM и не
   реализует полное наследование.
2. Maven учитывает BOM через `dependencyManagement` с `scope=import`, профили
   сборки и exclusions в полном объёме. Учебная реализация поддерживает только
   локальный `dependencyManagement` и не реализует импорт BOM и все правила
   exclusions.
3. Maven выполняет mediation конфликтующих версий и выбирает одну версию
   транзитивной зависимости. Приложение не повторяет весь алгоритм mediation.
4. Maven учитывает активные профили, настройки `settings.xml`, репозитории и
   версию Maven-плагина. Приложение читает POM напрямую из указанного URL.
5. Прямые optional-зависимости принадлежат текущему проекту, но не должны
   автоматически передаваться его потребителям. Приложение включает optional
   зависимости корневого пакета и исключает их при транзитивном обходе.

Для отчёта сохраните фактический вывод обеих команд из одного окружения.
Состав зависимостей сравнивайте для одного и того же выбранного артефакта,
отделяя корневой проект-потребитель Maven от поддерева этого артефакта.
